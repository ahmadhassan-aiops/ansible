# 01. Introduction to Ansible and Its Architecture

Ansible is a configuration management, automation and software deployment tool.

## Architecture of Ansible

The Ansible server (Ansible engine) communicates with machines (servers) through the **SSH** service.

**Communication types:**

1. **Ad-hoc command** → a simple command line, e.g. `free -g`
2. **Playbook** → a `.yml` file that holds the commands and says exactly what configuration to apply and which machines to target

## Example Architecture

We have Ansible installed, so we have an Ansible server (engine).

Now suppose we have 4 machines, each running a different OS:

| Machine | IP |
|---|---|
| server/node/machine-1 | 192.168.43.1 |
| server/node/machine-2 | 192.168.43.2 |
| server/node/machine-3 | 192.168.43.3 |
| server/node/machine-4 | 192.168.43.4 |

- The information about all these machines is kept in Ansible's **inventory** file, which lives in the `/etc/ansible` directory.
- In an ad-hoc command, you mention which machine to take from the inventory file (machine-1, 2, 3 or 4) and what to run on it.
- `ansible.cfg` is a very important file. It manages how Ansible works with the remote servers or machines.
