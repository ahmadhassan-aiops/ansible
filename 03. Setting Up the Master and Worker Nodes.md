# 03. Setting Up the Master and Worker Nodes

Ansible has a **master** node and **worker** nodes.

- Ansible communication is **agentless**: no agent is installed on the node machines. Ansible is installed only on the master machine, not on every worker node.
- Ansible communicates over SSH in two ways: ad-hoc commands and playbooks.
- SSH communication between the master and worker nodes uses either a password or password-less (key-based) authentication.

> **Always create a dedicated user for Ansible on the master machine in production. It is not good practice to work as root in production.**

| Role | OS | IP |
|---|---|---|
| Master | CentOS | 192.168.0.108 |
| Worker node | Ubuntu (AWS) | 54.166.4.83 |

## Install Python on the Node

```bash
sudo apt install python-is-python3
```

```console
ubuntu@ip-172-31-26-215:~$ python --version
Python 3.12.3
```

## Create the Ansible User

Create a user `john` on the master machine:

```bash
useradd -m -s /bin/bash john
```

Log in as `john`:

```bash
su - john
```

Add `john` to the sudoers file so that nothing `john` does asks for a password. Open the sudoers file:

```bash
visudo
```

Add this entry:

```
john ALL=(ALL) NOPASSWD:ALL
```

Make this entry on both systems, master and node.

**Why add `john` to the sudoers file?**

If you don't add an entry for `john` in visudo, you need to add `john` to the sudo group (`sudo usermod -aG sudo john`) and then set a password for `john` (`passwd john`, e.g. `john123`). Every time you install something, it asks for that password, which is tedious. With a `NOPASSWD` entry in visudo, `sudo apt install zip` no longer asks for a password, so the user works password-less.

## Enable Password Authentication

Open `/etc/ssh/sshd_config` on both master and node and check that `PasswordAuthentication` is `yes`. If it isn't, set it to `yes` on both machines.

```console
[root@client1 john]# cat /etc/ssh/sshd_config | grep -i PasswordAuthentication
#PasswordAuthentication yes
# PasswordAuthentication.  Depending on your PAM configuration,
# PAM authentication, then enable this but set PasswordAuthentication
```

Then restart the SSH service on both the master and node machine.

## Generate and Copy the SSH Key

Switch to your normal user on the master machine (here `john`) and generate a key:

```bash
ssh-keygen
```

Now copy this key to the worker node. Because the worker node here is an AWS EC2 Ubuntu instance, a small workaround is needed. First copy the `.pem` key to the master (from the MobaXterm terminal):

```bash
scp /drives/c/Users/<your-user>/Downloads/NVKP.pem john@192.168.0.108:/home/john/
chmod 400 /home/john/NVKP.pem
ssh -i /home/john/NVKP.pem ubuntu@54.166.4.83
```

Then, inside the SSH session on the Ubuntu machine, run:

```bash
mkdir -p ~/.ssh
echo "PASTE_YOUR_PUBLIC_KEY_HERE" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
chmod 700 ~/.ssh
```

Mention the user of the worker node when connecting, otherwise the root user of the worker node is used:

```bash
ssh ubuntu@54.166.4.83
```

## Add the Node to the Inventory

```bash
vim /etc/ansible/hosts
```

Make an entry for the Ubuntu node:

```
54.166.4.83 ansible_user=ubuntu
```

```console
[john@master-ansible ~]$ ansible all -m ping -u ubuntu --private-key=~/NVKP.pem
54.166.4.83 | SUCCESS => {
    "ansible_facts": {
        "discovered_interpreter_python": "/usr/bin/python3"
    },
    "changed": false,
    "ping": "pong"
}
```

Add the key file to the inventory entry so you don't have to pass it every time:

```bash
sudo vim /etc/ansible/hosts
```

```
54.166.4.83 ansible_user=ubuntu ansible_ssh_private_key_file=~/NVKP.pem
```

```console
[john@master-ansible ~]$ ansible all -m ping
54.166.4.83 | SUCCESS => {
    "ansible_facts": {
        "discovered_interpreter_python": "/usr/bin/python3"
    },
    "changed": false,
    "ping": "pong"
}
```

| Part | Meaning |
|---|---|
| `ansible` | Use Ansible |
| `all` | All nodes |
| `-m` | Module |
| `ping` | Run the ping module |
