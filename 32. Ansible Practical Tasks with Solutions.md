# 32. Ansible Practical Tasks with Solutions

## Task 1: Copy a File without a Playbook

**Question:** A file is located at `/home/user/data.csv`. Copy it with Ansible without using a playbook.

**Answer:** Use an ad-hoc command with the `copy` module.

```bash
ansible ubuntu -m copy -a "src=/home/user/data.csv dest=/tmp/data.csv" -b
```

| Part | Meaning |
|---|---|
| `ubuntu` | The group/host defined in your inventory (the AWS Ubuntu worker) |
| `src` | File on the Ansible master (CentOS VM) |
| `dest` | Location on the worker node (Ubuntu EC2) |
| `-b` | Run with sudo |

## Task 2: Get Memory Details with an Ad-Hoc Command

**Question:** Obtain the memory details of a remote host using an ad-hoc command.

**Answer:** Use the `setup` module to gather facts and filter the memory details. This shows the total memory in MB:

```bash
ansible ubuntu -m setup -a 'filter=ansible_memtotal_mb'
```

For all memory-related facts:

```bash
ansible ubuntu -m setup -a 'filter=ansible_memory*'
```

## Task 3: Get Memory Details with gather_facts

**Question:** As in Task 2, obtain the memory details, this time using Ansible's gather facts feature.

**Answer:** A small playbook that gathers the memory facts and prints them.

```yaml
# memory_facts.yml
---
- name: Gather memory facts from Ubuntu worker
  hosts: ubuntu
  gather_facts: yes
  tasks:
    - name: Print total memory
      debug:
        msg: "Total Memory: {{ ansible_memtotal_mb }} MB"
```

```bash
ansible-playbook memory_facts.yml
```

## Task 4: Copy and Extract an Archive

**Question:** Copy `application.tar.gz` to a remote endpoint and, once it is copied, extract it automatically with a playbook.

**Answer:** Use `copy` + `unarchive`.

```yaml
# copy_extract.yml
---
- name: Copy and extract application file
  hosts: ubuntu
  become: yes
  tasks:
    - name: Copy tar file
      copy:
        src: /home/user/application.tar.gz
        dest: /tmp/application.tar.gz

    - name: Extract tar.gz file
      unarchive:
        src: /tmp/application.tar.gz
        dest: /opt/app
        remote_src: yes
```

```bash
ansible-playbook copy_extract.yml
```

## Task 5: Install a Web Server and Open Port 80

**Question:** Install the httpd package and allow port 80/tcp in the firewall with a playbook.

**Answer:** On Ubuntu, install `apache2` and use `ufw` for the firewall.

```yaml
# httpd_firewall.yml
---
- name: Install Apache and allow port 80
  hosts: ubuntu
  become: yes
  tasks:
    - name: Install Apache2
      apt:
        name: apache2
        state: present
        update_cache: yes

    - name: Allow port 80 in firewall
      ufw:
        rule: allow
        port: 80
        proto: tcp
```

## Task 6: Deploy and Verify a Web Page

**Question:** Install and start the httpd service, copy `index.html` to the Apache server and verify that the web page is accessible.

```yaml
# deploy_web.yml
---
- name: Deploy web page with Apache
  hosts: ubuntu
  become: yes
  tasks:
    - name: Install Apache2
      apt:
        name: apache2
        state: present
        update_cache: yes

    - name: Start and enable Apache2 service
      service:
        name: apache2
        state: started
        enabled: yes

    - name: Copy index.html
      copy:
        src: /home/user/index.html
        dest: /var/www/html/index.html

    - name: Verify webpage
      uri:
        url: http://{{ inventory_hostname }}/index.html
        return_content: yes
      register: webpage

    - name: Show webpage content
      debug:
        msg: "{{ webpage.content }}"
```

## Task 7: Create a User and Allow It in sshd_config

**Question:** Create a new user and add it to the `AllowUsers` entry in `/etc/ssh/sshd_config` with Ansible.

```yaml
# ssh_user.yml
---
- name: Add user and update sshd_config
  hosts: ubuntu
  become: yes
  tasks:
    - name: Create user
      user:
        name: newuser
        password: "{{ 'Password@123' | password_hash('sha512') }}"

    - name: Add user to AllowUsers in sshd_config
      lineinfile:
        path: /etc/ssh/sshd_config
        regexp: '^AllowUsers'
        line: "AllowUsers newuser"
        create: yes
        backup: yes

    - name: Restart SSH service
      service:
        name: ssh
        state: restarted
```

## Task 9: Send a File to a Windows Machine

**Question:** Send a file to a Windows machine (192.168.0.1) with a playbook.

**Answer:** With Windows hosts, Ansible uses **WinRM** for communication and Windows-specific modules: instead of `copy`, we use `win_copy`.

```yaml
# send_file_windows.yml
---
- name: Send file to Windows machine
  hosts: windows
  vars:
    ansible_user: Administrator
    ansible_password: "{{ vault_windows_password }}" # stored encrypted with Ansible Vault
    ansible_connection: winrm
    ansible_winrm_transport: basic
  tasks:
    - name: Copy file to Windows
      win_copy:
        src: /home/user/data.txt
        dest: C:\Users\Administrator\Desktop\data.txt
```

**Explanation:**

- `hosts: windows` → your inventory should contain:
  ```ini
  [windows]
  192.168.0.1
  ```
- `win_copy` → the Windows version of the `copy` module.
- `src` → path on your Ansible master (CentOS).
- `dest` → path on the Windows machine.
- `vault_windows_password` → never write the real password in the playbook. Store it encrypted with `ansible-vault create secrets.yml` (containing `vault_windows_password: ...`), add `vars_files: [secrets.yml]` to the play, and run with `ansible-playbook send_file_windows.yml --ask-vault-pass`.
