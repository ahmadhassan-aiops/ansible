# 20. Variables, Type Checking and set_fact

`vars` defined outside the tasks act as global variables.

## Defining Variables and Checking Their Data Types

```yaml
# sudo vim data_type.yml
---
- name: this yml file is for understanding data types
  hosts: localhost
  vars:
    a: 15
    b: 20.1
    c: ahmad hassan
    d: True
  tasks:
  - name: using debug msg to display variables and their data types
    debug:
      msg:
      - "my number is {{a}} and its data type is {{a|type_debug}}"
      - "my decimal is {{b}} and its data type is {{b|type_debug}}"
      - "my name is {{c}} and its data type is {{c|type_debug}}"
      - "my boolean is {{d}} and its data type is {{d|type_debug}}"
```

```console
[john@master-ansible ansible]$ ansible-playbook data_type.yml

PLAY [this yml file is for understanding data types] *************************************************************************

TASK [Gathering Facts] *******************************************************************************************************
ok: [localhost]

TASK [using debug msg to display variables and their data types] *************************************************************
ok: [localhost] => {
    "msg": [
        "my number is 15 and its data type is int",
        "my decimal is 20.1 and its data type is float",
        "my name is ahmad hassan and its data type is AnsibleUnicode",
        "my boolean is True and its data type is bool"
    ]
}

PLAY RECAP *******************************************************************************************************************
localhost                  : ok=2    changed=0    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
```

> With `var`, you can only display the variable's value directly. With `msg`, you can call the variable using `{{ }}` and also add any custom text around it.

## vars vs set_fact (Interview Question)

1. **vars**: sets a variable that can be used across the entire playbook; you can call it anywhere.
2. **set_fact**: sets a host-specific variable within a task, based on a task result.

**Difference:**

1. `vars` defines a global variable.
2. `set_fact` sets a variable within the tasks of the same playbook.

```yaml
# vim set_var.yml
- name: This is example of vars and set_facts
  hosts: localhost
  gather_facts: false
  vars:
    ah: "Ahmad Hassan"
  tasks:
  - name: this is set_Facts example
    set_fact:
      xyz: "CloudOps"

  - name: Printing the variable from vars
    debug:
      var: ah
  - name: Print the variable from set_facts
    debug:
      var: xyz
```

If you define a variable in `vars` and in `set_fact` with the same name, `set_fact` overwrites it:

```yaml
# vim set_var_diff.yml
- name: This is example of vars and set_facts
  hosts: localhost
  gather_facts: false
  vars:
    ah: "Ahmad Hassan"
  tasks:
  - name: this is set_Facts example
    set_fact:
      ah: "CloudOps"

  - name: Printing the variable from vars
    debug:
      var: ah
  - name: Print the variable from set_facts
    debug:
      var: ah
```

Now `CloudOps` is displayed in both places.
