# 05. Ad-Hoc Commands

This topic covers creating and removing directories and files, transferring and fetching files, and installing packages on worker nodes.

Ansible communicates with remote nodes through:

1. **Ad-hoc commands**: used for a simple or single task on a remote machine.
2. **Playbooks**: can run multiple tasks at the same time.

## Running Commands on Worker Nodes

```bash
ansible machine_name -m shell -a command_to_run
```

Check the IP and memory of the Ubuntu worker node from the master node:

```bash
ansible ubuntu -m shell -a "ifconfig"
ansible ubuntu -m shell -a "free -g"
```

```console
[ubuntu@master-ansible ansible]$ ansible ubuntu -m shell -a "free -g"
54.166.4.83 | CHANGED | rc=0 >>
               total        used        free      shared  buff/cache   available
Mem:               0           0           0           0           0           0
Swap:              0           0           0
```

| Part | Meaning |
|---|---|
| `ansible` | Use Ansible |
| `ubuntu` | Worker machine name |
| `-m shell` | Module to run (shell on that machine) |
| `-a "ifconfig"` | Argument passed to the shell, i.e. the command |

## Using the Root User of the Worker Node

```bash
ansible ubuntu -m shell -a "df -h" --user=root --ask-pass
```

It asks for the root password of the Ubuntu machine. (When the worker node is an AWS EC2 Ubuntu instance, no SSH password is needed.)

> Warnings can be disabled by setting `deprecation_warnings=False` in `ansible.cfg`.

```bash
ansible ubuntu -m file -a "path=/home/ubuntu/test_ansible state=directory mode=0777"
```

```console
ubuntu@ip-172-31-26-215:~$ pwd
/home/ubuntu

ubuntu@ip-172-31-26-215:~$ ls
test_ansible
```

## shell vs command

You can use the `command` module in place of `shell`, but `command` does not work with pattern matching, wildcards or redirection.

```bash
ansible ubuntu -m shell -a "df -h"

# the same command using the command module
ansible ubuntu -m command -a "df -h"
```

## Working with Files

Create a directory named `TestAnsible` on the remote machine (Ubuntu):

```bash
ansible all -m file -a "path=/home/ubuntu/TestAnsible state=directory"
```

Create a text file in that path:

```bash
ansible all -m file -a "path=/home/ubuntu/TestAnsible/test.txt state=touch"
```

Remove the file:

```bash
ansible all -m file -a "path=/home/ubuntu/TestAnsible/test.txt state=absent"
```

Give or remove permissions on a file or directory (permissions are controlled by `mode`):

```bash
ansible all -m file -a "path=/home/ubuntu/TestAnsible/test.txt mode=0777"
```

> **Note:** I work as a normal user on the master machine and as a normal user on Ubuntu. Normal users are not allowed to create or remove files in directories such as `/etc`. To solve this, add the user to the sudoers file with the required permissions. `john` is my Ansible user on the CentOS 9 master machine:
>
> ```
> john ALL=(ALL)  NOPASSWD:ALL
> ```
>
> Now we can use the `-b` (become) argument with our commands.

```bash
ansible ubuntu -m file -a "path=/etc/testfile.txt state=touch mode=777" -b
```

`-b` does the same as running `sudo touch /etc/testfile.txt` as that user.

## Installing Packages on Remote Machines

You can install a package in two ways (`-b` for sudo):

```bash
ansible ubuntu -m shell -a "apt-get update && apt-get install -y zip" -b
ansible ubuntu -m apt -a "name=zip state=present update_cache=yes" -b
```

**For Ubuntu:**

```bash
# install
ansible ubuntu -m apt -a "name=zip state=present" -b

# uninstall
ansible ubuntu -m apt -a "name=zip state=absent" -b

# update
ansible ubuntu -m apt -a "name=zip state=latest" -b
```

**For RHEL/CentOS:**

```bash
# install
ansible ubuntu -m yum -a "name=zip state=present" -b

# uninstall
ansible ubuntu -m yum -a "name=zip state=absent" -b

# update
ansible ubuntu -m yum -a "name=zip state=latest" -b
```

## Transferring Files with Ad-Hoc Commands

| Tool | Use |
|---|---|
| `copy` | Copy files locally (used as a module in Ansible) |
| `scp` | Copy files from one system to another |
| `rsync` | Remote copy |

Transfer a file from the master to the worker:

```bash
ansible ubuntu -m copy -a "src=/home/john/ansible/master.txt dest=/home/ubuntu" -b
```

Write content directly into a file on the worker node (this overwrites the file):

```bash
ansible ubuntu -m copy -a "content='Hello this is ahmad' dest=/home/ubuntu/master.txt" -b
```

Create a backup of the old file, then write content directly into the file on the worker node:

```bash
ansible ubuntu -m copy -a "content='Hello this is sara' dest=/home/ubuntu/master.txt backup=yes" -b
```

## Fetching Files from Worker Nodes

To fetch files from the worker node to the master node, the source is the node and the destination is the master machine:

```bash
ansible ubuntu -m fetch -a "src=/home/ubuntu/master.txt dest=/home/john/ansible" -b
```

Not only is `master.txt` copied: a new directory named after the worker node's IP is created on the master, and the complete path is recreated:

```
192.168.43.63 → home → ubuntu → master.txt
```

This creates a nested directory structure, which is not ideal. Fetch without the directory structure:

```bash
ansible ubuntu -m fetch -a "src=/home/ubuntu/master.txt dest=/home/john/ansible/ flat=yes" -b
```

Fetch with the machine IP added to the file name:

```bash
ansible ubuntu -m fetch -a "src=/home/ubuntu/master.txt dest=/home/john/ansible/{{ inventory_hostname }}_master.txt flat=yes" -b
```

`inventory_hostname` → the IP address of the Ubuntu machine.
