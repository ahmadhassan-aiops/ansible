# 04. Understanding the ansible.cfg File

`ansible.cfg` is created in `/etc/ansible` along with the Ansible installation. If it isn't created, you can create it manually.

Back up the file and generate a full configuration with all options:

```bash
cp ansible.cfg ansible.cfg.bak
ansible-config init --disabled -t all > ansible.cfg
```

## Using a Per-User Configuration

Copy all files from `/etc/ansible/` into the home directory of the master-node user you created for managing the worker nodes (here `john`):

```bash
mkdir /home/john/ansible
cp -vrf /etc/ansible/* /home/john/ansible
```

Before copying, `ansible --version` showed the configuration file as `/etc/ansible/ansible.cfg`. Now move into `/home/john/ansible` and run `ansible --version` again: the config file path shows `/home/john/ansible`.

`ansible --version` shows the configuration file based on your present location: inside `/home/john/ansible` it uses `/home/john/ansible/ansible.cfg`, and from `/` it uses `/etc/ansible/ansible.cfg`.

## Setting a Fixed Configuration Path

To keep one fixed path, define it in an environment variable:

```bash
export ANSIBLE_CONFIG=/home/john/ansible
```

Now, wherever you are, the `.cfg` file is taken from `/home/john/ansible`.

> This environment variable is removed when the system restarts. You can make it permanent if needed.

## Setting the Inventory Path

Open `ansible.cfg`, find the inventory path and point it to your hosts file, so the worker nodes and their configuration are read from there:

```ini
inventory = /home/john/ansible/hosts
```

If your inventory file has another name, pass it with `-i`:

```bash
ansible -i /home/john/env -m ping
```

`-i` → inventory file path. By default the path set in `ansible.cfg` (`/home/john/ansible/hosts`) is used, but with `-i` the path you mention is used.

## Targeting Machines

Target a specific worker:

```bash
ansible worker_ip -m ping

# example
ansible 54.166.4.83 -m ping
```

Check more than one machine at once:

```bash
ansible machine_ip:second_machine_ip -m ping

# example
ansible 192.168.43.63:192.168.43.64 -m ping
```

In production we don't use IPs, we use machine names. For example, `54.166.4.83` is my web machine, so the hosts file has:

```ini
[web]
54.166.4.83
```

```bash
ansible web -m ping
```
