# 08. Understanding Ansible Playbooks

## What If Python Is Not Present on Worker Nodes?

The Ansible master communicates with worker nodes through Python. If Python is not installed on a worker node, can Ansible still communicate with it?

**Yes, by using the `raw` module.** The `shell` module uses Python for communication; when Python is not available on the worker node, the `raw` module communicates directly through the socket instead.

Remove Python from a worker node and use `raw` from the master; it still succeeds:

```bash
ansible ubuntu -m raw -a "ifconfig"
```

## Ansible Playbook

> *A playbook in Ansible is a set of instructions.*

- Instructions are written in a YAML file: `.yml` or `.yaml` (`.yml` is recommended).
- The YAML script performs the specified tasks on the worker nodes.
- A playbook is like a compose file that plays (runs) a set of tasks.

## Theory of a Playbook

| Part | Purpose |
|---|---|
| **hosts** | The list of worker or remote nodes |
| **variables** | Data that can be customized through variables |
| **tasks** | The actions you want to perform: installing packages, managing services, etc. |
| **handlers** | Notifying other tasks |

All of these are written in the playbook, which is run to execute the YAML script and perform the tasks it mentions.

## Ansible Playbook vs Ad-Hoc Commands

- Ad-hoc commands are useful for one-time tasks; playbooks are useful for multiple tasks.
- Ad-hoc commands are used for small changes; for multiple changes we prefer playbooks.
- Playbooks keep your automation structured and organized. For complex requirements, use a playbook rather than ad-hoc commands.
- Ad-hoc commands are used for troubleshooting because they give quick results.

## YAML Files

- YAML is not a markup language; it is a human-readable data serialization format.
- It is good practice to start a YAML file with three dashes `---`.
- We write tasks in an Ansible playbook.

```yaml
# vim apache2.yml
---
- name: Installing apache package
  yum:
    name: httpd
    state: latest
```

**Playbook for installing Apache:**

```yaml
# vim apache.yml
---                                  # start of the yml file
- name: This yaml file focus on installation of apache2   # name of the play
  hosts: ubuntu                      # worker node where apache2 will be installed
  become: yes                        # run commands with sudo privileges
  tasks:
    - name: Install apache2          # task name or description
      yum:                           # task to perform
        name: apache2                # package name to install
        state: present               # state of the package: install, update or remove
```

Run the playbook:

```bash
ansible-playbook -i hosts apache.yml
```

If the inventory is already set in `ansible.cfg` and the SSH key is installed:

```bash
ansible-playbook apache.yml
```

## Installing Multiple Packages

**Key=value style with `yum`** (my worker machine is Ubuntu, so this one will not work there):

```yaml
---
- name: this file installs multiple package
  hosts: centos
  become: yes
  tasks:
    - name: Installation of zip
      yum: name=zip state=present
    - name: Installation of wget
      yum: name=wget state=present
```

**This one works on Ubuntu:**

```yaml
---
- name: this file installs multiple packages
  hosts: ubuntu
  become: yes   # so you don't need "sudo" in shell
  tasks:
    - name: Install multiple packages
      apt:
        name:
          - zip
          - wget
        state: present
        update_cache: yes
```

**To make the playbook work on both Ubuntu and CentOS:**

```yaml
---
- name: Install packages on multiple OS types
  hosts: all
  become: yes
  tasks:
    - name: Install on Debian/Ubuntu
      apt:
        name:
          - zip
          - wget
        state: present
        update_cache: yes
      when: ansible_os_family == "Debian"

    - name: Install on CentOS/RedHat
      yum:
        name:
          - zip
          - wget
        state: present
      when: ansible_os_family == "RedHat"
```
